# rm_control 模块详细分析

## 核心功能
`rm_control` 是 RM 机械臂 ROS2 控制栈的**轨迹执行引擎**，负责：
1. 接收 MoveIt2 规划的轨迹
2. 通过三次样条插值生成光滑轨迹
3. 以 50Hz 频率周期性地发送控制指令给硬件驱动

---

```

│                    MoveIt2 规划器                               │
│  生成轨迹：10-20个稀疏路点 + 时间戳 + 速度 + 加速度              │
└────────────────────────┬────────────────────────────────────────┘

│ │  - 生成1000+个密集路点                                  │   │
```

## 数据流详解

### 第1阶段：数据接收 (execute_move)

```cpp
// MoveIt发送的轨迹消息结构：
trajectory {
    points[0] {
        positions = [0.0, 0.5, 0.2, 1.0, 0.3, -0.5, 0.0]    // 7轴关节位置
        velocities = [0.0, 0.1, 0.05, 0.1, 0.05, 0.05, 0.0]  // 7轴关节速度
        accelerations = [0.0, 0.05, 0.02, 0.05, 0.02, 0.02, 0.0]  // 加速度
        time_from_start = {sec: 0, nanosec: 0}   // 起点时间
    }
    points[1] {
        positions = [0.1, 0.6, 0.25, 1.1, 0.35, -0.4, 0.05]
        velocities = [0.1, 0.15, 0.1, 0.15, 0.1, 0.1, 0.05]
        accelerations = [0.05, 0.1, 0.05, 0.1, 0.05, 0.05, 0.02]
        time_from_start = {sec: 1, nanosec: 200000000}  // 1.2秒
    }
    ...
    points[n] {
        positions = [...] 
        velocities = [...]
        accelerations = [...]
        time_from_start = {sec: 4, nanosec: 800000000}  // 4.8秒
    }
}
```

**数据提取步骤：**
```
原始数据 (n=5个路点):
├─ 时间戳: [0, 1.2, 2.4, 3.6, 4.8] 秒
├─ Joint1: [0, 0.1, 0.2, 0.3, 0.4] rad
├─ Joint2: [0.5, 0.6, 0.7, 0.8, 0.9] rad
├─ Joint3: [0.2, 0.25, 0.3, 0.35, 0.4] rad
├─ Joint4: [1.0, 1.1, 1.2, 1.3, 1.4] rad
├─ Joint5: [0.3, 0.35, 0.4, 0.45, 0.5] rad
├─ Joint6: [-0.5, -0.4, -0.3, -0.2, -0.1] rad
└─ Joint7: [0, 0.05, 0.1, 0.15, 0.2] rad
```

### 第2阶段：三次样条插值

对**每个关节**独立执行插值：

```
Joint1 插值过程：
┌─ 输入：
│  ├─ x_data (时间): [0, 1.2, 2.4, 3.6, 4.8]
│  ├─ y_data (位置): [0, 0.1, 0.2, 0.3, 0.4]
│  ├─ 边界条件：v_0=0, v_end=0 (一阶导数)
│  └─ 数据点数：5
│
├─ spline.loadData() 
│  └─ 追赶法求解三对角方程组
│     计算每个数据点的二阶导数 M_[]
│
└─ 输出：内部样条系数已计算完成
   可以用 getYbyX() 查询任意时间点的值

插值计算（循环）：
x_out = -0.02
while (x_out < 4.8) {
    x_out += 0.02  // 20ms时间步长
    spline.getYbyX(x_out, y_out)
    
    结果：
    x_out=0.00 → y_out=0.000
    x_out=0.02 → y_out=0.0003
    x_out=0.04 → y_out=0.0012
    ...
    x_out=4.78 → y_out=0.399
    x_out=4.80 → y_out=0.400
}

生成的插值点数：240个 (4.8 / 0.02 = 240)
```

**插值效果对比：**
```
时间坐标轴 (秒)：
0    1.2   2.4   3.6   4.8
|----|----|----|----|
●    ●     ●     ●     ●      <- MoveIt 原始5个路点

0.00 0.02 0.04 ... 4.78 4.80
|||||||||||||||||||||||||||||  <- 插值后240个密集点 (50Hz采样)
```

**数学原理：三次样条插值**

对于区间 `[x_i, x_{i+1}]`，构造三次多项式：
```
S_i(x) = a_i + b_i(x-x_i) + c_i(x-x_i)^2 + d_i(x-x_i)^3
```

满足条件：
1. 插值条件：`S_i(x_i) = y_i` 且 `S_i(x_{i+1}) = y_{i+1}`
2. 连续条件：相邻段在连接点处值、一阶导数、二阶导数都连续
3. 边界条件：两端点的导数由用户指定（通常设为0表示平稳）

结果：**生成C²连续曲线**（位置、速度、加速度都连续光滑）

### 第3阶段：周期发送 (timer_callback)

**全局数据结构：**
```cpp
struct vel_data {
    int vector_len;    // 插值后的总点数（如240）
    int vector_cnt;    // 当前发送点的索引（0～239）
};

struct vel_data p2;
bool point_changed;   // 标志位：true=有新轨迹，false=已全部发送
```

**发送流程时间线：**
```
t=0ms     t=20ms    t=40ms    t=60ms    ...    t=4800ms   t=5940ms
|         |         |         |                 |          |
点[0]      点[1]     点[2]     点[3]     ...    点[239]    保持点[239]×1.5秒
p2.cnt++  p2.cnt++  p2.cnt++  p2.cnt++         point_     (共75次发送)
                                               changed=
                                               false
```

**单次发送的消息内容：**
```cpp
// 时刻 t=0.02*n 秒
joint_msg {
    joint[0] = p_joint1_[n];   // Joint1 位置
    joint[1] = p_joint2_[n];   // Joint2 位置
    joint[2] = p_joint3_[n];   // Joint3 位置
    joint[3] = p_joint4_[n];   // Joint4 位置
    joint[4] = p_joint5_[n];   // Joint5 位置
    joint[5] = p_joint6_[n];   // Joint6 位置
    joint[6] = p_joint7_[n];   // Joint7 位置（7轴）
    follow = follow_;          // 跟踪参数
}

发布到话题：/rm_driver/movej_canfd_cmd
```

### 第4阶段：硬件执行

rm_driver 接收后：
```cpp
1. 解析 joint_msg 消息
2. 组装 TCP 指令格式
3. 通过 TCP (192.168.1.188:8081) 发送给控制器
4. 控制器执行关节运动

同时，控制器通过 UDP (9501) 以 50Hz 频率发送实时反馈：
└─ 7个关节的当前位置
└─ 7个关节的电流
└─ 传感器数据等
```

## 三次样条插值算法详解

### 为什么需要插值？

**问题**：MoveIt 只规划 10-20 个路点，如果直接发送这么少的路点：
- 机械臂会在路点间做直线插值（默认行为）
- 结果：轨迹呈折线状，有尖刺和抖动
- 危害：机械臂受冲击，电机噪音大，精度低

**解决方案**：
- 使用三次样条插值
- 将 10-20 个点扩展到 1000+ 个点
- 以 50Hz（20ms）的频率平稳发送
- 结果：轨迹光滑连续，机械臂运动平稳

### 插值步骤详解

**步骤1：追赶法求解二阶导数**

构造三对角方程组：
```
系数矩阵形式：
    [b0  c0   0   0   0 ] [M0]   [d0]
    [a1  b1  c1   0   0 ] [M1]   [d1]
    [0   a2  b2  c2   0 ] [M2] = [d2]
    [0   0   a3  b3  c3 ] [M3]   [d3]
    [0   0   0   a4  b4 ] [M4]   [d4]
    
其中：
M_i = 二阶导数（加速度）
a_i, b_i, c_i = 系数矩阵元素
d_i = 右侧常数项
```

**步骤2：追赶法求解**

```
扫描过程（从上到下）：
bt_i = c_i / (b_i - a_i * bt_{i-1})
gm_i = (d_i - a_i * gm_{i-1}) / (b_i - a_i * bt_{i-1})

回代过程（从下到上）：
M_i = gm_i - bt_i * M_{i+1}
```

结果：得到每个数据点的二阶导数 M_[0]~M_[n]

**步骤3：查询任意点的值**

在区间 [x_i, x_{i+1}] 内，位置为：
```
y(x) = y_i + (某些系数) * (x-x_i) + ...
```

位置对时间求导得速度：
```
v(x) = dy/dx = b_i + 2*c_i*(x-x_i) + 3*d_i*(x-x_i)^2
```

再求导得加速度：
```
a(x) = dv/dx = 2*c_i + 6*d_i*(x-x_i)
```

### 性能对比

```
方案1：直接发送MoveIt的10个路点
├─ 通信量：少
├─ 轨迹质量：差（折线状，有尖刺）
├─ 机械臂体验：差（冲击、噪音、易摔）
└─ 总体效果：不推荐

方案2：三次样条插值后发送1000个点
├─ 通信量：多（但5ms发送一次，总耗时不变）
├─ 轨迹质量：优（完全光滑，C²连续）
├─ 机械臂体验：优（平稳运动，精度高）
└─ 总体效果：推荐使用
```

## 状态机流程

```
┌──────────────────────────────────────────────────┐
│         等待新轨迹（point_changed=false）         │
└──────────────────┬───────────────────────────────┘
                   │
              MoveIt发送新轨迹
                   │
                   ↓
┌──────────────────────────────────────────────────┐
│  execute_move() 线程开始                         │
│  - 提取轨迹数据                                  │
│  - 对6/7关节应用三次样条插值                     │
│  - 生成1000+个插值点                            │
│  - 存到全局向量                                  │
│  - 设置 point_changed=true                      │
└──────────────────┬───────────────────────────────┘
                   │
                   ↓
┌──────────────────────────────────────────────────┐
│  execute_move() 进入等待循环                     │
│  while(point_changed) {                         │
│      检查是否被中止                              │
│      sleep(2ms)                                  │
│  }                                               │
└──────────────────┬───────────────────────────────┘
                   │ (定时器会在后台发送)
                   ↓
┌──────────────────────────────────────────────────┐
│  timer_callback() 循环执行 (每20ms)             │
│  发送轨迹的插值点                                │
│  p2.vector_cnt 从 0 递增到 p2.vector_len       │
└──────────────────┬───────────────────────────────┘
                   │
          (当所有点都发送完)
                   │
                   ↓
┌──────────────────────────────────────────────────┐
│  timer_callback() 进入保持阶段                   │
│  继续发送最后一个点 1.5 秒                       │
│  count_final_joint 从 0 递增到 count_keep_send  │
└──────────────────┬───────────────────────────────┘
                   │
        (当保持阶段也完成)
                   │
                   ↓
┌──────────────────────────────────────────────────┐
│  重置所有状态变量                                │
│  - point_changed = false                        │
│  - p2.vector_cnt = 0                            │
│  - count_final_joint = 0                        │
└──────────────────┬───────────────────────────────┘
                   │
          execute_move() 等待循环结束
          返回成功完成结果给MoveIt
                   │
                   ↓
┌──────────────────────────────────────────────────┐
│         回到初始状态，等待新轨迹                  │
└──────────────────────────────────────────────────┘
```

## 调试和优化建议

### 1. 插值精度调整
```cpp
double rate = 0.020;  // 20ms = 50Hz

// 如果轨迹不够光滑，减小 rate：
rate = 0.010;  // 10ms = 100Hz（效果更光滑，但点数翻倍）

// 如果通信量过大，增加 rate：
rate = 0.050;  // 50ms = 20Hz（点数减少，可能有轻微抖动）
```

### 2. 保持时间调整
```cpp
float wait_move_finish_time = 1.5;  // 轨迹完成后再保持1.5秒

// 如果机械臂还没完全到位就开始下一条轨迹，增加此值：
wait_move_finish_time = 2.0;

// 如果反应时间要求高，可以减小：
wait_move_finish_time = 1.0;
```

### 3. 故障排查

| 现象 | 原因 | 解决方案 |
|------|------|---------|
| 轨迹执行不动 | rm_driver 没有启动 | 检查 `ros2 node list` |
| 轨迹抖动 | 插值精度不足或通信延迟 | 减小 `rate` 或检查网络 |
| 机械臂过度摆动 | MoveIt速度规划不当 | 在 MoveIt 配置中降低最大速度 |
| 偶发执行失败 | 轨迹路点数 ≤ 3 | MoveIt 规划失败，重新规划 |

## 总结

`rm_control` 的核心作用就是**轨迹平滑**：
1. 接收 MoveIt 的稀疏轨迹（10-20个点）
2. 使用三次样条插值扩展成密集轨迹（1000+个点）
3. 以 50Hz 频率周期性发送给硬件
4. 确保机械臂运动平稳、光滑、无抖动

这种设计完全不同于标准 ROS2 的 `ros2_control` 框架，而是采用了**直接 TCP/UDP 通信**的方式，为 RM 机械臂提供了更灵活、更实时的控制。
