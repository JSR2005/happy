## 🔄 核心数据流

### 数据流 1️⃣: 用户命令 → 机械臂执行

```
用户在 RViz 设置目标 (或通过脚本)
    │ (拖动交互标记)
    ▼
move_group 节点
    ├─ 计算逆运动学 (IK)
    ├─ 运行 OMPL 规划器
    └─ 生成轨迹
    │
    ▼
/rm_group_controller/joint_trajectory 话题
    │ (轨迹消息)
    ▼
rm_group_controller 订阅
    ├─ 跟随轨迹
    └─ 计算关节命令
    │
    ▼
gazebo_ros2_control 桥接
    │ (ROS2 Control → Gazebo)
    ▼
Gazebo 虚拟机械臂执行

⏱️  总延迟: 500ms (规划) + 200ms (执行) + 100ms (反馈) ≈ 800ms
```

### 数据流 2️⃣: 硬件状态 → 用户可视化

```
Gazebo 虚拟机械臂
    │ (更新关节位置)
    ▼ [20ms, 50Hz]
gazebo_ros2_control 读取状态
    ▼
joint_state_broadcaster 发布
    │ /joint_states [50Hz]
    ├────────────────┬─────────────┐
    ▼                ▼             ▼
robot_state_pub  move_group    监视工具
计算 /tf          同步状态      显示数值
    │
    ▼
/tf 话题 [50Hz]
    │
    ▼
RViz 订阅
    │
    ▼
3D 显示更新

⏱️  延迟: 20ms (1个控制周期)
```

### 数据流 3️⃣: 碰撞检测可视化

```
move_group 规划时
    │ (计算碰撞)
    ▼
/display_contacts 发布
    │ (碰撞点标记数组)
    ▼
RViz MarkerArray 显示器
    │
    ▼
在 3D 视图中显示红色球体 (碰撞点)
```

## 🎯 关键节点角色分析

### 核心节点 (必须运行)

#### 1. **Gazebo** - 物理仿真
- **职责**: 提供虚拟环境和物理模拟
- **发布**: /clock (仿真时钟, 同步全系统)
- **作用**: 所有时间同步的基准

#### 2. **joint_state_broadcaster** - 关节状态反馈
- **职责**: 从虚拟硬件读取关节状态
- **发布**: /joint_states (50Hz, 关键反馈)
- **作用**: 整个系统的状态基准

#### 3. **robot_state_publisher** - TF树生成
- **职责**: 计算机械臂的正向运动学
- **发布**: /tf (50Hz, 所有链接位姿)
- **作用**: RViz 显示和运动学计算的基础

#### 4. **rm_group_controller** - 轨迹执行
- **职责**: 跟随规划的轨迹
- **订阅**: /rm_group_controller/joint_trajectory
- **作用**: 将规划转化为硬件命令

#### 5. **move_group** - 轨迹规划
- **职责**: 规划碰撞无碰撞的轨迹
- **提供**: /compute_ik, /compute_fk, /move_group/move_action
- **作用**: 整个系统的智能中枢

### 支持节点 (增强功能)

- **RViz**: 可视化前端,用户交互入口
- **controller_manager**: 控制器生命周期管理
- **moveit_simple_controller_manager**: MoveIt2 与 ROS2 Control 适配器
- **RQT**: 调试和监控工具

## ⚡ 快速查询指南

### 查看系统状态

```bash
# 查看所有运行的节点
ros2 node list

# 查看节点关系图 (推荐)
ros2 run rqt_graph rqt_graph

# 查看所有话题
ros2 topic list -t

# 查看 TF 树
ros2 run tf2_tools view_frames.py && open frames.pdf
```

### 监控关键数据

```bash
# 监控关节状态 (每秒更新一次)
watch 'ros2 topic echo /joint_states 1'

# 监控话题频率
ros2 topic hz /joint_states
ros2 topic hz /tf
ros2 topic hz /clock

# 查看末端位置
ros2 run tf2_ros tf2_echo base_link Link6_tool0
```

### 测试核心功能

```bash
# 测试逆运动学
ros2 service call /compute_ik moveit_msgs/srv/GetPositionIK \
"{ ... }"

# 发送运动命令
ros2 action send_goal /move_group/move_action moveit_msgs/action/MoveGroup \
"{ ... }"

# 检查碰撞
ros2 service call /check_state_validity moveit_msgs/srv/GetStateValidity \
"{ robot_state: {} }"
```

### 系统诊断

```bash

ros2 topic hz /joint_states && \
ros2 topic hz /tf && \
```

## 🔧 常见问题快速解决

### Q1: 机械臂不动?
```bash
# 检查列表
1. ros2 node list | grep rm_group_controller
2. ros2 topic echo /joint_states 1
3. ros2 topic echo /clock 1
4. ros2 service call /controller_manager/list_controllers
```

### Q2: RViz 显示错误?
```bash
# 检查列表
1. ros2 topic echo /robot_description 1
2. ros2 run tf2_tools view_frames.py
3. ros2 topic hz /tf
4. ros2 topic hz /joint_states
```

### Q3: 规划失败?
```bash
# 检查列表
1. ros2 service call /compute_ik ...
2. ros2 topic echo /tf 1
3. 检查关节限制 (URDF 中的 limit 标签)
4. 检查目标点是否在工作空间内
```
